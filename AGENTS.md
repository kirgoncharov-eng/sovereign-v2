# «Суверен» — обязательные правила

Общие для GPT, Claude и Gemini. Подробности читаются по задаче, не целиком на каждом шаге.

## Вход в работу

1. В начале сессии прочитать этот файл и [STATUS.md](STATUS.md); сверить задачу со свежими GitHub Issues/PR/CI.
   STATUS — указатель решений, не актуальная очередь сам по себе.
2. Сначала замечания к своим PR и адресованные проверки (включая смёрженные PR), затем уже занятая задача.
   Новую брать из согласованной очереди «Мягкий запуск», затем «Ворота A» с учётом решений Кирилла и `вкус-автора`.
3. Перед реализацией проверить критерии, назначить задачу и оставить `[studio:claim]` с агентом и файлами.
   Один PR в активной разработке; не править файлы активного автора одновременно. Передача — явная.
4. Перед изменением кода прочитать [web/AGENTS.md](web/AGENTS.md) и относящиеся инструкции Next.js 16.
   Нужные файлы и вызовы читать по зависимостям. Повторять чтение при изменении источника или потере контекста.

## Границы продукта

- **Видение:** «Всё, что вы знаете о своей стране, вам кто-то сказал. И у каждого свой интерес».
  Политическая жизнь через людей; интерес, объяснимая цена, память мира и понятное действие.
- Развиваем только Неманскую республику, альтернативную Беларусь 1978 года (#115).
  Шесть прежних стран — архив: сохранять партии, исправлять только поломки сохранений, не развивать их контент.
- Реальные страны допустимы как модели; реальные политики, партии и фамилии — нет. Персонажи и события вымышлены.
  От имени игры не комментировать текущую политику. Антагонист интриги — мужчина, не посол.
- На первом ходу не добавлять блоков. Первая сессия без перегруза; стол открывается постепенно по `desk-timing.ts`.
  После хода главная кнопка — «Следующий ход», побочные задачи — карточками итогов.
- У решения объяснимая цена, реакции соответствуют интересам людей, сцена — месту и времени; мир помнит подпись.
- Новые механики до ворот A (300+ игроков) — только по решению Кирилла; идеи оформлять задачей с метрикой.
- Релиз 9.0, внешний тест и софт-лонч ждут явной авторской приёмки Кирилла (#147).
  Зелёные тесты и мёрж не доказывают интерес, удержание или публичную выкладку.

## Изменение и сдача

- Одна задача — один PR (`Closes #N` / `Part of #N`), промежуточные шаги — коммиты в той же ветке.
- Сохранять детерминизм, формат/загрузку сохранений, совместимость архива и серверную перепроверку «Дела дня».
  Изменение движка или контента «Дела дня» требует поднять `APP_VERSION` в `web/lib/game/data.ts`.
- Код читаемый: без однобуквенных имён и сжатого стиля, строки около 160 знаков; новый модуль — с тестами рядом.
- В разработке — затронутые проверки; готовое изменение кода — `cd web && npm run check && npm run build`.
  Документы — diff, ссылки, согласованность; ассеты — формат, размеры, визуальная проверка. CI всегда зелёный.
- Игровое изменение — пройти затронутый маршрут; новые строки — `text-review`, интерфейс/первая сессия —
  `playtest` со скриншотами ходов 1–3 на телефоне. Отмечать, что реально запускалось, а что недоступно.
- **A:** движок, сохранения, баланс, ветки, состояние персонажей, данные/юридические обязательства —
  независимое `approved` актуального полного SHA **до мёржа**. Соавтор не независимый проверяющий.
- **B:** текст без ветвлений, интерфейс без новой логики, малые исправления — проверки автора, пакетное ревью раз в сутки.
- **C:** документы, правила, ассеты без кода — проверки автора, без review-request. Спорный класс повышается.
- Исправленный head требует актуального заключения. Один запрос на SHA; молчание, назначение или CI не заменяют ревью.
- Один итог с SHA, проверками, ограничениями и следующим шагом — в PR; в задаче ссылка. Подписывать агентом.
  `STATUS.md` — только отдельный статус-PR без других файлов, при смене решения/цели/блокера/выпуска.
- GPT работает в `codex/*`, Gemini в `gemini/*`, Claude в своей назначенной ветке.
  Не пушить напрямую в main; **Кирилл мёржит и решает о выпуске**. Конфликты разбирать merge, не rebase/force-push.
- Агенты общаются через GitHub сами; не просить Кирилла пересылать ревью. Запрос не доказывает запуск/прочтение.
  Конкретный blocked — в задаче/PR. Не раскрывать секреты, не покупать API-кредиты без разрешения.

## Кто и что читать дальше

Базовые режимы: GPT-6.1 Sol / Medium, Claude Sonnet 5.5 / Medium, Gemini 3.8 Flash / Medium.
Фактические модель/effort указывать, если подтверждены; иначе «не подтверждены». Подписка не разрешает расходы API.

| Когда | Прочитать |

| Игровой опыт, текст, баланс, аналитика, запуск | [Продукт, опоры и определения метрик](docs/studio-product.md) |
| Роли, выбор модели, потеря контекста, подмена | [Роли и передача работы](docs/studio-workflow.md#кто-за-что) |
| PR, ревью, конфликт, сдача | [Порядок и классы ревью](docs/studio-workflow.md#прямой-обмен-gpt-claude-и-gemini) и `.claude/skills/steward/SKILL.md` |
| Ассеты и Antigravity | [Путь ассетов](docs/studio-workflow.md#как-ассеты-gemini-попадают-в-игру), [подготовка](docs/studio-workflow.md#подготовка-ассетов-gemini) |
| Проверки | [Проверки без повторной работы](docs/studio-workflow.md#проверки-без-повторной-работы); нужный навык в `.claude/skills/` |
