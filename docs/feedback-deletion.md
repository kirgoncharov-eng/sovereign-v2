# #112 — удаление данных Telegram

15 октября 2026. GPT/Codex. Исправление ошибки, класс A; готовность к закрытому тесту,
а не доказанный рост D1/D7. Игровой движок, сохранения и APP_VERSION не меняются.

## Подтверждённый пользователь

Webhook проверяет Telegram secret до handleUpdate (прежняя граница доверия).
Новые отзывы принимают автора только из message.from.id или callback_query.from.id:
положительный целый ID должен совпадать с ID личного чата. Группа, отсутствующий from.id
и чужой отправитель не могут оставить отзыв от имени чата или вызвать удаление его данных.
Имя/username — подпись, не ключ удаления; API анонимного отзыва игры не принимает авторство Telegram.

/forget удаляет подписку, незаконченный опрос, очередь followup, взаимные связи друзей,
результаты/имя в индексированных версиях Daily, отзывы с совпавшим telegramUserId.
Точные строки списка удаляются через LREM: параллельно пришедший чужой отзыв не теряется.
Для предотвращения повторного followup по старому initData остаётся только запрет рассылки
(OPT_OUT). Команда /start либо явная подписка его снимает; это открыто сказано в ответе и /privacy.

## Срок Daily

freshDate разрешает дату D до начала D+2 (UTC), а последняя отправка продлевает TTL на72ч.
Поэтому ещё жива таблица D−4; старый обход D−2…D+1 был недостаточен.
Новый обход: D−4…D+1 включительно, обычные ключи и все ключи из daily:date:editions.
Удаляется только свой uid. Другие результаты/индексы сохраняются.
Проверка — данные на дальних датах D−4/D−3/D+1 с двумя игроками.

## Учтённые копии у автора

Новый отзыв получает UUID. До отправки Telegram записывается намерение в
fb:copies:<userId>, поле UUID. После успешного sendMessage там хранятся исходный chat_id
и message_id: смена администраторского чата и вытеснение из списка500 не теряют копию.
UUID напечатан в копии, чтобы её можно было найти и при таймауте без message_id.
Явный отказ sendMessage снимает намерение; таймаут/неполный ответ не считаются отсутствием копии.

/forget вызывает deleteMessage для каждой известной копии. Только ok:true снимает запись.
При отказе/неизвестном результате указатели остаются; fb:cleanup содержит userId → время запроса.
Это служебная очередь с адресами сообщений, без дополнительного текста отзыва.
Повторный /forget повторяет попытки и не возвращает уже удалённые записи.
Бот сообщает о незавершённой ручной очистке, а не обещает уничтожение всех копий.

Ограничение API: https://core.telegram.org/bots/api#deletemessage — сообщения старше48ч
обычно нельзя удалить ботом. Молчание Telegram, истечение времени и отсутствие записи
в списке500 не являются подтверждением очистки копии.

### Ручная очистка: порядок для автора игры

Этот PR не выполняет очистку production и не подтверждает, что оператор её уже сделал.
Доступ к очереди — только в административном Redis, не публичная страница/команда.
1. Прочитать HGETALL fb:cleanup; для userId — HGETALL fb:copies:<userId>.
2. В сохранённом chat найти message_id; при неизвестном message_id искать точный UUID.
3. Удалить именно найденную копию в Telegram вручную и проверить её отсутствие.
4. Только после проверки снять соответствующее поле UUID через HDEL. Не удалять копии
   других пользователей, не сопоставлять их по одному имени. Если копия не установлена,
   запрос остаётся pending. Отсутствие доступа к старому админскому чату не означает очистку.
5. Когда все записи пользователя действительно очищены, снять поле userId в fb:cleanup.
   Оператор может вместо этого после удаления всех UUID повторить /forget для снятия pending.

Нельзя объявлять пользователю подтверждённый срок ручной обработки без принятого оператором
обязательства. PR не вводит обещаний о времени ответа. Полный контакт/оператор и общая политика — #114.

## Наследованные данные и границы

Старые отзывы без telegramUserId остаются: удалять все записи Alex или @oldname небезопасно.
Точный текст старого отзыва можно прислать через /feedback для уточнения автором.
Старые неучтённые копии нельзя восстановить из новых индексов. Эти ограничения явно указаны
в ответе /forget и /privacy, даже если все новые учтённые копии удалены.
Анонимные отзывы из игры, сообщения в чате самого игрока, общие анонимные счётчики этим
запросом не удаляются. Указатели/очередь копий хранятся до фактического подтверждения очистки;
нельзя ставить TTL, который выдаст потерю указателя за удаление сообщения.

## Маршрут проверки

Без сети Telegram/production Redis: подписанный источник → /feedback → два ответа → оценка,
смена username → /forget; сосед с тем же first_name остаётся. Отдельно: нет имени/ID,
группа/чужой отправитель, старые записи, отказ/таймаут Telegram, смена admin-chat,
вытеснение списка, повторное удаление, поздняя Daily, друзья, followup/старый initData.
Тесты используют только память и заглушку fetch. Тесты не подтверждают реальное удаление
в Telegram и не заменяют независимое ревью/операционную приёмку #114.
