## Потоки и хранилища

в проверенном коде, а не утверждённый бессрочный срок. TTL Redis может продлеваться при записи.

## Идентифицируемость и доступ

Track не добавляет имя/Telegram ID в тело события, но использует стабильный UID,
который Daily посылает рядом с подписанными данными Telegram. Поэтому «анонимная статистика»
и «связать с человеком нельзя» — недоказанные утверждения. Отдельного постоянного Redis-словаря
UID → Telegram ID в проверенных маршрутах не найдено; это не доказывает невозможность сопоставления.

Сам UID не секрет: он используется в ссылках приглашения. Он не подтверждает владение данными.
Автоматического доступа/выгрузки/удаления серверной PID-аналитики сейчас нет.
Его нельзя имитировать открытым endpoint «удалить по известному PID».
Для новой реализации нужен проверяемый механизм владения, состав очищаемых ключей,
обработка агрегатов/копий, повторов и неполного результата; отдельная узкая задача до кодирования.

Действующий канал ручного уточнения — `/feedback` в личном чате бота. Он сам создаёт отзыв
и копию автору; это не отдельная система исполнения запросов и не гарантированный срок ответа.
Не запрашивать пароли, bot token или initData. Для bot-отзыва право на `/forget` подтверждается
private `from.id == chat.id`; имя, присланный ID или публичная ссылка не заменяют проверку.
Ручная очистка копий описана в `docs/feedback-deletion.md`.

## Провайдеры и недостающие решения

| Пункт | Что установлено | Что требуется, кто решает |
| --- | --- | --- |
| Vercel | Деплой репозитория на Vercel; публичные сообщения build существуют | Регион функций, логи/резервные копии, реальные сроки и DPA не проверены; проверяет оператор с доступом |
| Redis | Код использует REST Upstash/Vercel KV; без настройки — память процесса | Реальный ресурс, регион, резервные копии, договор/сроки и настройки доступа не проверены; не читать секреты для карты |
| Telegram | SDK, initData, CloudStorage, Bot API, сообщения/копии | Условия/роли и передачи оцениваются после выбора оператора и рынков; не выдавать разрешение писать за маркетинговое согласие |
| Оператор и рынки | В задаче не выбраны | Кирилл определяет издателя/страны/контакт; затем правовая проверка целей, оснований, прав и передач |
| Сроки без TTL | Перечислены фактические пробелы, а не новая политика | Оператор утверждает конкретные сроки, основания и последствия удаления; затем узкие задачи на миграцию/истечение |
| BotFather | Код setupProfile настраивает команды, описание и меню | Своя privacy policy в BotFather не подтверждена; наличие `/privacy` этого не доказывает; нужен просмотр настройки владельцем |
| LocalStorage / сообщения | UID/канал сохраняются; `/start` подписывает; разрешение писать допускает followup | Для выбранных рынков определить требования к аналитике и сообщениям; регрессии `/stop`/`/forget` уже есть |
| Доступ и стирание PID/meta | Автоматического полного процесса нет | Согласовать безопасное подтверждение владения, облачное удаление и ручную очередь; не обещать их текущей командой |
| Продажи | Платёжной логики в проверенных маршрутах не найдено | До продажи: издатель, законный платёжный путь, вывод и возвраты; не реализуется этим PR |
