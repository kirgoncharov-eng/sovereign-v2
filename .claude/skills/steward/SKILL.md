# Ведение PR

- **Входящие.** В начале сессии и перед новой задачей проверить запросы и ответы в обсуждениях PR,
  включая недавно смёрженные. Указатель — STATUS.md, фактические сообщения — GitHub.
- **Передача между агентами.** Следовать разделу «Прямой обмен GPT и Claude» в AGENTS.md:
  review-request → review-ack → review-result; исправление → review-fixed → повторная проверка.
  Указывать подпись агента и полный SHA; не просить пользователя пересылать сообщения.
- **Готовность.** Проверка автора не заменяет независимую. Новый head требует актуального заключения.
  После мёржа проверить код в main: мёрж в промежуточную ветку не означает доставку задачи.
- **Ветки.** Claude работает в своей назначенной ветке; GPT/Codex — в ветках `codex/*`, Gemini — `gemini/*`. В `main` никто не пушит напрямую, мёржит только пользователь.
- **Перед пушем** — `cd web && npm run check && npm run build`. Красный CI не пушить «на авось».
- **CI.** Задача `check` — линтер, типы, тесты, сборка. Задача `playtest` — партия в браузере; её папка со скриншотами лежит в артефактах запуска. Упал `playtest` — смотреть `summary.json`: `problems` объясняет причину.
- **STATUS.md.** В рабочем PR не трогать — только отдельный статус-PR без других файлов; CI это проверяет.
- **Конфликты.** Вливать `origin/main` в свою ветку (merge, не rebase). Автор чужого PR недоступен — см. AGENTS.md,
  «Конфликт с `main` в чужом PR». Чаще всего конфликтуют `web/app/game/SovereignGame.jsx`, `web/lib/game/classic.ts`, `web/lib/game/living-world.ts` — разбирать по смыслу, не «взять мою версию».
- **Ревью чужого PR** (в том числе от GPT) — по правилам из корневого `AGENTS.md`: метрика в описании, тесты, скриншоты, первая сессия не тяжелее, читаемый стиль. Замечания — конкретные, с файлом и строкой.
- **Флейки.** «Нестабильный тест» — не причина. Падение в CI воспроизвести локально и найти причину. Тесты не отключать.
- **Версия.** Изменения движка или контента «Дела дня» — с поднятой `APP_VERSION`.
