# Ведение PR

Классы, проверки и условия мёржа — в корневом `AGENTS.md`; не дублировать их отдельным регламентом.
Для текущего действия читать нужный раздел [координации](../../../docs/studio-workflow.md):
«PR и ревью», а при остановке автора — «Передача и подмена».

- Проверять свои входящие и обсуждение текущего PR, включая смёрженный, если в нём открыт запрос.
- C не требует независимого ревью или review-request. A требует approved на актуальный SHA; B проверяется пакетом.
- Во время работы — затронутые проверки; полный check/build на готовом коде. Для документов — diff и ссылки.
  Не повторять успешный полный прогон без влияющих правок, ошибки или новой неопределённости. Обязательный CI остаётся.
- `check` в CI: линтер, типы, тесты, сборка. `playtest`: браузерная партия, кадры в артефакте;
  причину падения искать в `summary.json` → `problems`. «Флейк» не объясняет причину; тесты не отключать.
- Итог — в PR, из задачи ссылка. STATUS обновляется при смене цели/блокера/выпуска отдельным PR, не ежедневно.
- Ветки Codex — `codex/*`, Gemini — `gemini/*`, Claude — назначенная ветка. Не пушить в main; мёржит Кирилл.
- Конфликты разрешать по смыслу merge-коммитом с main. Частые пересечения:
  `SovereignGame.jsx`, `classic.ts`, `living-world.ts`. После мёржа проверить попадание в main; выкладку подтверждать отдельно.
