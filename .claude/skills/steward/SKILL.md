# Ведение PR

- Следовать [AGENTS.md](../../../AGENTS.md); детали — в [studio-workflow.md](../../../docs/studio-workflow.md).
  Уже прочитанный актуальный источник не перечитывать на каждом вызове.
- В начале сессии сверить входящие к своим PR и адресованные проверки, включая смёрженные PR; STATUS — только указатель.
- Claim и файлы — в задаче до правок. Работать в своей ветке, не занимать файлы другого действующего автора.
- В разработке запускать затронутые проверки; на готовом изменении кода — `cd web && npm run check && npm run build`.
  Документы: diff, ссылки, согласованность. Ассеты: формат, размер, визуальная проверка. CI зелёный для всех классов.
- A: независимое approved полного актуального SHA до мёржа. B: один запрос пакетного ревью на SHA.
  C: проверки автора, без review-request. Собственная/соавторская проверка не независимая.
- Повторное ревью: исправления и зависимости; не повторять неизменённый аудит без нового риска.
  Не наследовать одобрение старого SHA. Отличать локальную проверку, CI и слова автора.
- Упал playtest — смотреть summary.json в артефакте. Ошибку воспроизвести и объяснить, тесты не отключать.
- Конфликт: merge origin/main, не rebase/force-push. Чужой автор недоступен — правила подмены в workflow.
- Один итог с SHA, реальными проверками, ограничениями и следующим шагом — в PR; в задаче ссылка.
  Handoff только при передаче/остановке; один запрос на SHA, без дублирующих комментариев.
- STATUS.md менять только отдельным статус-PR при смене цели/решения/блокера/выпуска, не вести там ежедневную очередь.
- Кирилл мёржит и решает о выпуске. После мёржа проверить код в свежей main; мёрж не доказывает выкладку.
- Движок/контент «Дела дня» — поднять APP_VERSION. Конкретно отметить недоступные проверки и не выдавать diff за тесты.
