# Аудит

Аудит отвечает на три вопроса: работает ли игра, стала ли она лучше для игрока, идём ли к коммерческой версии (цели и метрики — в корневом `AGENTS.md`).

## Шаги

1. **Что изменилось.** `git fetch origin main`, список PR и коммитов с даты прошлого аудита (дата — последняя запись в Notion «Аудиты»). Размер: `git diff --stat <прошлый коммит> origin/main | tail -1`.
2. **Код.** `cd web && npm run check` (линтер, типы, тесты) и `npm run build`. Записать число тестов и вес главного JS-файла:
   `ls .next/static/chunks/*.js | xargs -I{} sh -c 'gzip -c {} | wc -c' | sort -n | tail -1`.
3. **Стиль.** Новые модули без сжатого стиля: `awk 'length>300' <файл> | wc -l` — должно быть 0.
4. **Движок.** `node scripts/stress.ts` — 0 падений и 0 пустых слотов; отметить повторяющиеся фразы.
5. **Игра глазами игрока.** Скилл `playtest`.
6. **Текст.** Скилл `text-review` на 2–3 странах.
7. **Блокеры запуска.** Пройти список из прошлой записи аудита: что закрыто, что нет.
8. **Метрики.** Проверить доступ к `/api/stats` через имеющиеся инструменты и разрешённую авторизацию.
   При фактическом отсутствии доступа попросить цифры; без свежих данных так и написать. Секреты не выводить.
9. **Запись в Notion.** Через подключённый Notion найти базу «Аудиты» на странице «Суверен» и проверить её схему.
   Известный ID: `d393ec7c-b51e-4cf7-b500-4a0fbe5cb4e1`; использовать только после подтверждения базы.
   Новая запись: Дата, Вердикт, Блокеров, Тесты, Коммит, метрики; в тексте — вывод, качество,
   продуктовые сомнения, блокеры, ценность и следующий шаг. Если запись недоступна, сохранить итог локально и сообщить ограничение.
10. **Ответ пользователю** — короткий вывод и ссылка на запись.

## Как оценивать траекторию

Каждый крупный блок изменений — через вопрос «какую метрику он двигает». Глубина без данных об игроках — это не прогресс к коммерческой версии. Честно писать, если работа ушла в сторону.
