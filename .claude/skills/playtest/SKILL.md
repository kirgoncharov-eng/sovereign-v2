# Плейтест

Цель — увидеть игру глазами игрока, а не только тестами: перегружен ли первый экран, не застревает ли партия, нет ли ошибок.

## Шаги

1. Из корня проекта: `cd web && npm ci && npm run playtest:install`. Нужен Node.js 22 или новее.
   В облачной сессии Claude с готовым Chromium пропустить `playtest:install`: установка браузера там может быть запрещена.
   Playwright закреплён в проекте; Chromium устанавливается один раз, повторно — при смене версии Playwright.
2. Запустить партию (команда сначала собирает актуальное демо):
   ```
   npm run playtest -- --turns=24 --out=playtest
   ```
   Для более длинной партии — `--turns=40`; для превью Vercel — `--url=<адрес превью>`.
   Для отдельного результата — `--out=<папка>`. Все команды выполняются из `web`.
   Если в среде Codex нет Node.js в PATH, получить путь через `load_workspace_dependencies`;
   npm должен быть доступен отдельно. Не считать наличие встроенного Node.js установленным npm.
   В CI это делает задача `playtest` сама и прикладывает папку к запуску.
3. Прочитать `summary.json`: `problems` должен быть пустым. Код выхода 1 — есть проблема.
4. Открыть PNG доступным просмотрщиком изображений: `turn-1.png`, `turn-1-result.png`, `turn-2…`, `turn-3…`, `end.png`. Смотреть как игрок:
   - на первом ходу только дело, резолюция и мандат — никаких «Сообщений» и «Правительства»;
   - главная кнопка после хода — «Следующий ход»;
   - текст не перекрыт нижней панелью, ничего не вылезает за экран;
   - газета не повторяет вчерашние строки.
5. Итог — коротко: сколько ходов, ошибки, что видно на скриншотах, что перегружено. Скриншоты с проблемами — показать пользователю.

## Чего не делать

- Не править скрипт под конкретную партию, чтобы он «прошёл». Если скрипт застрял на новом экране — это или ошибка игры, или новый экран, который скрипт должен научиться проходить; научить и написать об этом.
